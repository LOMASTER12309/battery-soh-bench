# vibe-team: оценка SOH методом ElasticNet

## 1. Назначение и результат

Решение оценивает SOH отдельного зарядного фрагмента по кривой нормированного
заряда, току, температуре и положению окна напряжения. Используется линейная
регрессия ElasticNet по 52 признакам масштаба, формы и условий измерения.

Итоговая конфигурация: hybrid, alpha = 0.001, l1_ratio = 0.05,
без перевзвешивания обучающих строк. Финальная модель обучена на объединении
train и val: 3977 фрагментов, 110 физических ячеек.

Файл submission.csv содержит 2015 прогнозов для test_unlabeled.parquet.
Официальные результаты на скрытой разметке NCA/NMC и LFP пока не получены.
Приведённые далее ошибки относятся к открытым размеченным данным.

## 3. Данные и доступные входы

| Набор | Фрагменты | Физические ячейки | Применение |
|---|---:|---:|---|
| train.parquet | 2276 | 98 | Подбор параметров и обучение перед оценкой val |
| val.parquet | 1701 | 12 | Отложенная оценка после выбора параметров |
| train + val | 3977 | 110 | Обучение финальной модели |
| test_unlabeled.parquet | 2015 | Метаданные ячеек отсутствуют | Формирование submission.csv |

Данные читаются из общей папки data/fragments/ репозитория. Дополнительные
данные не используются. Пересечение cell_id между train и val проверяется
скриптом и не допускается.

Один фрагмент содержит окно шириной 0.2 В и 128 точек каждого канала.
Точки расположены равномерно по напряжению, а не по времени.
В модель передаются только:

- v_start и v_end — границы окна;
- q_norm — нормированный заряд;
- current — ток;
- temperature — температура.

fragment_id используется только для сопоставления предсказаний.
cell_id применяется для разделения фолдов, диагностических группировок
и экспериментального варианта весов. cycle_index и идентификаторы
не включаются в признаки. soh используется только как целевая переменная.

Все признаки рассчитываются независимо для одного фрагмента. История ячейки,
соседние фрагменты и порядковый номер цикла для предсказания не требуются.
Проверяются конечность входов, ширина окна и длина каждого канала.

## 4. Вычисление признаков

### 4.1. Сглаживание и координаты

Для сглаживания q_norm применяется фильтр Савицкого — Голея:
длина окна 11 точек, степень полинома 3. Пусть s — сглаженный канал,
u — относительная координата окна от 0 до 1, а d — прирост заряда:

~~~text
d = s[127] - s[0]
r(u) = (s(u) - s[0]) / max(abs(d), 1e-8)
~~~

r описывает форму после удаления начального смещения и нормировки
на модуль прироста. Порог 1e-8 защищает деление и логарифм в почти плоском окне.
Производная сглаженного заряда вычисляется по напряжению V,
а производная нормированной формы — по относительной координате u.

### 4.2. Группы признаков

| Семейство | Число признаков | Состав |
|---|---:|---|
| baseline | 23 | Статистики исходного заряда, его интеграл и наклон, dQ/dV, ток, температура, границы окна |
| shape | 30 | Нормированная форма и контекст измерения |
| compact | 35 | shape, прирост заряда, его логарифм, смещение и взаимодействия |
| hybrid | 52 | Объединение baseline и compact с удалением повторяющихся имён |

Блок baseline соответствует публичному набору bsb.window_features.
Он включает среднее, стандартное отклонение, минимум, максимум и последнее
значение исходного q_norm; интеграл по напряжению и наклон между концами окна;
среднее, стандартное отклонение, минимум, максимум и центральное значение
сглаженной dQ/dV; границы и шаг напряжения; статистики тока и температуры.
Статистики самого q_norm рассчитываются до сглаживания, производная — после.

Блок нормированной формы содержит:

- значения r в девяти относительных положениях 0.1, 0.2, ..., 0.9;
- интеграл и стандартное отклонение r;
- стандартное отклонение, квантили 0.1 и 0.9 и медиану dr/du;
- среднее и стандартное отклонение отклонения r(u) - u;
- индикатор abs(d) < 1e-8.

Контекст включает границы окна, средние и стандартные отклонения тока
и температуры, а также фиксированные нелинейные преобразования.
Для их вычисления используются v = (v_start + v_end)/2 - 3.5
и t = (mean(temperature) - 25)/20:

~~~text
v², t², log1p(abs(mean(current))),
v * mean(current), v * t, mean(current) * t
~~~

compact добавляет d, log(max(abs(d), 1e-8)), s[0],
d * v и d * mean(current). В выбранном hybrid сохраняются и исходный масштаб,
и нормированная форма. Размерность 52 относится к входу Pipeline,
до удаления признаков с почти нулевой дисперсией.

## 5. Регрессия и обработка прогноза

Обучаемая последовательность:

~~~text
52 признака
→ VarianceThreshold(threshold=1e-12)
→ StandardScaler
→ ElasticNet
→ ограничение предсказания диапазоном [0.4, 1.1]
~~~

VarianceThreshold удаляет признаки с дисперсией не выше заданного порога.
StandardScaler вычитает среднее и делит на стандартное отклонение.
Оба преобразования обучаются только на обучающей части соответствующего
фолда и затем применяются к отложенной части. Целевой SOH не стандартизуется.

Для выбранного варианта без весов ElasticNet минимизирует:

~~~text
(1 / (2n)) * Σ(y_i - b - x_i·w)²
+ alpha * l1_ratio * ||w||₁
+ alpha * (1 - l1_ratio) * ||w||₂² / 2
~~~

b — свободный член, w — коэффициенты стандартизованных признаков.
Свободный член не штрафуется. Обучение минимизирует квадрат ошибки
с регуляризацией; выбор гиперпараметров производится по MAE.

| Параметр выбранной модели | Значение |
|---|---|
| feature_set | hybrid |
| alpha | 0.001 |
| l1_ratio | 0.05 |
| weighting | none |
| max_iter | 20000 |
| tol | 1e-5 |
| selection | cyclic |
| precompute | True |
| random_state | 42 |

Обучение численных библиотек ограничено одним потоком.
В финальной модели после обучения на train + val остаются 49 признаков:
удалены v_width, dqdv_step и flat_window. Ненулевых коэффициентов — 41.
Финальная модель сошлась за 7580 итераций. Число 43 в локальном отчёте
n_nonzero_coefficients относится к другой модели — обученной только на train
для оценки val.

Границы [0.4, 1.1] заданы в конфигурации до оценки val и одинаковы
для CV, val и финального предсказания. Это ограничение конкретной модели,
а не универсальный физический диапазон SOH. Верхняя граница выше единицы:
в train присутствуют метки до 1.09049. До ограничения проверяется отсутствие
NaN и бесконечностей в исходных предсказаниях.

## 6. Протокол подбора и оценки

1. Из train формируются пять фолдов GroupKFold(shuffle=False) по cell_id.
   Фрагменты одной физической ячейки не разделяются между обучающей
   и отложенной частями одного фолда.
2. На одинаковых фолдах сравниваются все 168 комбинаций из config.yaml.
3. Для каждой комбинации объединяются отложенные прогнозы всех пяти фолдов.
   Критерий выбора — MAE по всем train-фрагментам после ограничения прогноза.
4. 35 комбинаций, не сошедшихся в пределах max_iter, исключаются из выбора.
   Выбранная комбинация сошлась во всех пяти фолдах.
5. Выбранная модель обучается на всём train и оценивается на val.
   Val не используется для выбора признаков, гиперпараметров, весов
   или границ прогноза.
6. С выбранными настройками модель заново обучается на train + val.
   Именно эта финальная модель формирует submission.csv.

Пространство поиска:

| Настройка | Значения |
|---|---|
| feature_sets | baseline, shape, compact, hybrid |
| alphas | 0.0001, 0.0003, 0.001, 0.003, 0.01, 0.03, 0.1 |
| l1_ratios | 0.05, 0.5, 0.95 |
| weighting | none, cell_sqrt |

В экспериментальном cell_sqrt вес строки пропорционален
1/sqrt(числа фрагментов её ячейки). Количества считаются только по обучающей
части фолда, веса нормируются до среднего 1 и передаются StandardScaler
и ElasticNet. В выбранном решении этот вариант не используется.

OOF-метрики участвуют в подборе параметров и не являются полностью независимой
оценкой выбранного решения. Отложенная проверка val выполнена после выбора,
но описывает модель train-only. После финального обучения на train + val
эти строки уже не являются отложенными для итоговой модели.

## 7. Определения метрик

Все ошибки выражаются в процентных пунктах SOH. Для каждой строки:

~~~text
e_i = 100 * (soh_pred_i - soh_i)
MAE = mean(abs(e_i))
Bias = mean(e_i)
Max = max(abs(e_i))
P95 = quantile(abs(e_i), 0.95, method="linear")
~~~

Положительный Bias означает завышение SOH.
P95 — порог, ниже которого находится примерно 95% абсолютных ошибок;
он не равен максимальной ошибке. Для n отсортированных ошибок линейный
процентиль использует индекс h = 0.95 * (n - 1), считая с нуля,
и интерполяцию между соседними значениями.

MAE и P95 OOF рассчитываются по объединённым ошибкам всех фолдов,
а не как среднее метрик отдельных фолдов. Общая MAE взвешивает фрагменты
одинаково; отдельные ячейки могут иметь разное число фрагментов.

## 10. Воспроизведение

### 10.1. Окружение

Проверено на Windows с Python 3.12.10, CPU. PyTorch, CUDA и GPU не требуются.
Все зависимости исполнения закреплены в requirements.txt:
NumPy 2.5.3, Polars 1.44.2, SciPy 1.18.1, scikit-learn 1.9.1,
joblib 1.6.0, threadpoolctl 3.7.0, PyYAML 6.0.3 и указанные там зависимости.

Далее приведены команды PowerShell. Из корня репозитория:

~~~powershell
cd submissions/vibe-team
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
~~~

### 10.2. Полное обучение и получение CSV

Из папки submissions/vibe-team/:

~~~powershell
./.venv/Scripts/python.exe -B train.py --config config.yaml
./.venv/Scripts/python.exe -B predict.py
~~~

Первый запуск повторяет весь поиск по 168 комбинациям, оценку val
и финальное обучение. Он создаёт отсутствующие модель и отчёты.
Второй загружает созданный Pipeline и записывает submission.csv.

В уже подготовленном общем окружении репозитория, содержащем версии
из requirements.txt, эквивалентны команды из папки команды:

~~~powershell
uv run --locked --no-sync python -B train.py --config config.yaml
uv run --locked --no-sync python -B predict.py
~~~

### 10.3. Пути и интерфейс

Путь data_dir в config.yaml разрешается относительно самого config.yaml.
Пути артефактов и отчётов определяются относительно расположения train.py.
Для штатного запуска сохраняется структура submissions/vibe-team/
внутри репозитория с общими data/fragments/.

predict.py поддерживает явные пути:

~~~powershell
./.venv/Scripts/python.exe -B predict.py --model artifacts/model.joblib --input ../../data/fragments/test_unlabeled.parquet --output submission.csv
~~~

Его пути по умолчанию вычисляются от расположения скрипта; явно переданные
относительные пути считаются от текущей рабочей папки.
Для повторного предсказания после обучения достаточно predict.py.

### 10.4. Проверка CSV

Само решение не импортирует bsb. Для официального локального валидатора
нужно общее окружение репозитория, установленное по корневому README.
Из корня репозитория:

~~~powershell
uv run --locked bsb --config configs/benchmark.yaml validate --submission submissions/vibe-team/submission.csv
~~~

CSV содержит только fragment_id и soh_pred, сохраняет порядок строк
входной таблицы и записывает прогнозы с десятью знаками после запятой.
Контролируются уникальность и полнота идентификаторов, конечность прогнозов,
допустимый диапазон (0, 1.2] и размер не более 250000 байт.

## 12. Ограничения текущего решения

Отложенная проверка содержит всего 12 физических ячеек и существенно
смещена по доле источников. Групповой CV проверяет перенос между ячейками
из представленных источников, но не заменяет проверку на другом источнике
или химии.

Полностью исключённые источники дают заметно большие ошибки. На наиболее
состаренных примерах val наблюдается завышение SOH; на тестовых входах
сохраняется экстраполяция выше установленной границы. Наличие нормированных
признаков формы само по себе не доказывает физическую универсальность модели.

Модель является эмпирической регрессией зарядного окна. Электрохимические
уравнения, явная модель старения и физические ограничения монотонности
по циклам в ней не задаются.
